# ก่อนเปิดใช้จริง — ล้างข้อมูลทดสอบและตรวจการตั้งค่า

เอกสารนี้ตอบคำถาม "ถ้าจะ clear ข้อมูลก่อนขึ้น production ต้องทำอะไรบ้าง"

งานแบ่งเป็น 3 ส่วน และ **ต้องทำทั้ง 3 ส่วน** — ล้างเฉพาะฐานข้อมูลจะเหลือไฟล์ค้างใน
Storage และการตั้งค่าที่ยังชี้ไปของทดสอบ

---

## 0. ก่อนเริ่ม — สำรองข้อมูล

Supabase → **Database → Backups** ดาวน์โหลดไฟล์สำรองเก็บไว้ หรือ

```bash
pg_dump "postgresql://postgres:<password>@db.<project-ref>.supabase.co:5432/postgres" \
  --clean --if-exists -f backup-before-launch.sql
```

ทำก่อนเสมอ สคริปต์ล้างข้อมูลย้อนกลับไม่ได้

---

## 1. ฐานข้อมูล

ใช้ **`supabase/reset-before-launch.sql`** เปิดใน Supabase → SQL Editor

สคริปต์แบ่งเป็น 5 ขั้น รันขั้นที่ 0 ก่อนเพื่อดูว่าจะลบใครบ้าง (อ่านอย่างเดียว)
แล้วค่อยรันขั้นที่เหลือใน transaction เดียว ตรวจผลก่อน `COMMIT`

**ต้องแก้ก่อนรัน:** เปลี่ยน `'owner@example.com'` เป็นอีเมลบัญชีแอดมินของคุณ
มีอยู่ **3 ที่** ในไฟล์ (ขั้นที่ 0 สองที่ และขั้นที่ 1 หนึ่งที่) **ต้องตรงกันทั้งหมด** —
ถ้าขั้นที่ 1 พิมพ์ผิด บัญชีแอดมินจะถูกลบไปด้วย

**ทางเลือกที่ปลอดภัยกว่าถ้าไม่อยากแตะ `auth.users` ตรง ๆ:** ใช้ Supabase Admin API
(`auth.admin.deleteUser`) ลบทีละคน หรือกดลบจาก Supabase → Authentication → Users
ผลเหมือนกันเพราะ FK cascade ทำงานอยู่ดี แต่ให้ auth service จัดการ session และ
identity ของตัวเองด้วย — เหมาะเมื่อมีผู้ใช้ทดสอบไม่กี่คน

### หลักการที่สคริปต์ใช้

| ประเภท                      | ทำอะไร                                                                                                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ข้อมูลของคน**             | ลบ `auth.users` แล้วปล่อยให้ FK `ON DELETE CASCADE` ลบตามไปเอง — เอกสาร งาน เงิน ครอบครัว แผนมรดก ร้านค้า แผนเที่ยว แชท ทั้งหมด                                                                   |
| **บัญชีแยกและ audit**       | 4 ตารางที่ตั้งใจให้รอดตอนลบผู้ใช้ (`account_deletions`, `privacy_audit_log`, `donations`, `premium_payments`) ต้อง `TRUNCATE` แยก เพราะใช้ `SET NULL` ไม่ใช่ `CASCADE`                            |
| **ตัวนับและ log**           | `usage_daily`, `ai_token_usage`, `ai_usage_monthly`, `ai_events`, `notification_log`, `cron_ticks` และล้าง `last_run_at` ของ `automation_rules`                                                   |
| **ข้อมูลอ้างอิง — เก็บไว้** | `benefits` (แคตตาล็อกสิทธิรัฐ), `automation_rules` (23 กฎ พร้อมค่าพารามิเตอร์), `platform_settings` (ราคา สวิตช์ฟีเจอร์ ลิงก์คู่มือ), `ai_settings`, `donation_settings`, `notification_settings` |
| **สถานที่ตัวอย่าง**         | แถวจาก migration ตั้ง `is_active = false, is_demo = true` ไว้แล้ว จึงไม่โผล่ให้ผู้ใช้เห็น — จะลบด้วยก็ได้ (มีบรรทัด comment ไว้ให้)                                                               |

**ทำไมลบ `auth.users` ก็พอ:** migration `20260927110000_pdpa_user_fks.sql` ผูก 34 คอลัมน์
เข้ากับ `auth.users` และทดสอบการลบผู้ใช้จริงมาแล้ว — นี่คือกลไกเดียวกับปุ่ม "ลบบัญชีของฉัน"
ในหน้าตั้งค่า ต่างกันแค่ทำทีเดียวหลายคน

## 2. Storage (ไฟล์)

**SQL ลบไฟล์จริงไม่ได้** — ลบแถวใน `storage.objects` ได้ แต่ไฟล์จะค้างอยู่ในถังและยังคิดพื้นที่

ระบบใช้ถังเดียวชื่อ **`documents`** เก็บทุกอย่างไว้ใต้โฟลเดอร์ `{user_id}/`

- เอกสารที่อัปโหลด (คลังเอกสาร)
- หลักฐานงาน (ช่วยฉันที) ใต้ `job-evidence/`
- วิดีโออำลาและไฟล์ memorial
- หลักฐานประกัน/การชำระเงินของแผนงานศพ

**วิธีล้าง:** Supabase → **Storage → documents** → เลือกโฟลเดอร์ของผู้ใช้ทดสอบ → Delete
(โฟลเดอร์ชื่อเป็น UUID ของผู้ใช้ ดูรายชื่อ UUID ได้จากขั้นที่ 0 ของสคริปต์ **ก่อน** ลบผู้ใช้)

หรือใช้ Management API / `supabase storage rm` ถ้าไฟล์เยอะ

> ⚠️ **ทำตามลำดับ:** จด UUID ของผู้ใช้ทดสอบไว้ก่อน แล้วค่อยลบผู้ใช้ ไม่งั้นจะไม่รู้ว่า
> โฟลเดอร์ไหนเป็นของใคร

## 3. การตั้งค่าที่ต้องตรวจก่อนเปิดใช้

ส่วนนี้ไม่เกี่ยวกับการล้างข้อมูล แต่เป็นของที่ "ตั้งไว้ตอนทดสอบ" และต้องตรวจก่อนมีผู้ใช้จริง

| ที่ไหน                              | ตรวจอะไร                                                                                                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **บัญชีแอดมิน**                     | หลังล้างข้อมูล ตรวจว่าบัญชีที่เก็บไว้ยังมีแถวใน `public.user_roles` เป็น `admin` อยู่ — ถ้าไม่มีจะเข้า `/admin` ไม่ได้                                             |
| **`/admin` → สวิตช์ฟีเจอร์**        | เปิด/ปิดให้ตรงกับที่ต้องการเปิดใช้จริง (Google Places คิดเงินต่อครั้ง)                                                                                             |
| **`/admin` → ลิงก์คู่มือ**          | ใส่ลิงก์ Dropbox ที่ลงท้าย `?raw=1`                                                                                                                                |
| **`/admin` → กฎอัตโนมัติ**          | ตรวจค่าพารามิเตอร์ของ 23 กฎ (จำนวนวัน เปอร์เซ็นต์) ให้เหมาะกับผู้ใช้จริง                                                                                           |
| **`/admin` → ราคา/ค่าธรรมเนียม**    | commission / service fee / PromptPay ID                                                                                                                            |
| **Netlify → Environment variables** | `GOOGLE_MAPS_API_KEY` (ต้องเป็น key ที่ไม่จำกัด referrer เพราะเรียกจากฝั่ง server), `LINE_*` ครบ 4 ตัว, คีย์ AI provider                                           |
| **LINE Developers Console**         | Callback URL ต้องมี `https://<โดเมนจริง>/line/callback`                                                                                                            |
| **โดเมนจริง**                       | ถ้าย้ายจาก `lavieos.netlify.app` ไปโดเมนของตัวเอง ต้องแก้ Callback URL ของ LINE และ Site URL / Redirect URLs ใน Supabase → Authentication → URL Configuration ด้วย |
| **Supabase → Auth**                 | เปิดยืนยันอีเมล ตั้งค่า SMTP ของตัวเอง (ค่าเริ่มต้นของ Supabase จำกัดจำนวนอีเมลต่อชั่วโมง ไม่พอสำหรับผู้ใช้จริง)                                                   |
| **Scheduled function**              | ตรวจว่า `netlify/functions/tick.mts` ยังรันทุก 5 นาที (ดู `last_run_at` ในหน้ากฎอัตโนมัติหลังผ่านไป 5 นาที)                                                        |

## 4. ตรวจหลังล้าง

1. สมัครบัญชีใหม่หนึ่งใบเหมือนผู้ใช้จริง — ต้องได้อีเมลยืนยัน
2. หน้า **วันนี้** ต้องขึ้น 0 ทุกช่อง ไม่มีของค้างจากการทดสอบ
3. หน้า **ของดีใกล้บ้าน** ต้องไม่มีร้านทดสอบ
4. `/admin/usage` ต้องเริ่มนับจากศูนย์
5. `/admin/rules` ต้องยังมีครบ 23 กฎพร้อมค่าพารามิเตอร์
6. หน้า **สิทธิฉัน** ต้องยังมีแคตตาล็อกสิทธิครบ

ถ้าข้อ 5 หรือ 6 ว่าง แปลว่าล้างเกิน — กู้จากไฟล์สำรองในขั้นที่ 0
