# การแจ้งเตือนผ่าน LINE OA — ส่งอะไรบ้าง

สรุปจากโค้ดจริง (`src/lib/cron.server.ts`, `src/lib/line-deliver.server.ts`, `src/lib/line-flex.ts`)

## สรุปสั้นที่สุด

**LINE OA ส่งเฉพาะเรื่องที่เกี่ยวกับ "เรื่องที่ต้องทำ" เท่านั้น มี 2 แบบ**
เรื่องอื่นทั้งหมดอยู่ใน **การแจ้งเตือนในแอป** (`/inbox` + จุดแดง) ไม่ถูกส่งเข้า LINE

**ไม่มีการแยกตาม role** — admin กับผู้ใช้ทั่วไปได้รับเหมือนกันทุกประการ
สิ่งที่กำหนดว่าจะได้รับหรือไม่คือ **เชื่อมบัญชี LINE แล้วหรือยัง** และ **เป็นเพื่อนกับ OA อยู่หรือไม่**

---

## 1. สองแบบที่ส่งผ่าน LINE จริง

| แบบ                          | เกิดเมื่อ                                  | ส่งเมื่อ                                                                                                | หน้าตาข้อความ                                                                                                                         |
| ---------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **`immediate`** — เตือนทันที | งานที่ถึงกำหนด และตั้ง **ความสำคัญ = สูง** | ทันทีในรอบ tick ถัดไป (ทุก 5 นาที)                                                                      | การ์ด 1 งาน: ชื่องาน · **กำหนด** (วัน-เวลา) · **ความสำคัญ** (ตัวแดงเมื่อสูง) · **ทำซ้ำ** (ถ้ามี) · **หมายเหตุ** (ถ้ามี) + ปุ่มเปิดแอป |
| **`digest`** — สรุปรวมรายวัน | งานที่ถึงกำหนด และความสำคัญ **ปกติ/ต่ำ**   | รวมทั้งวันไว้ในแถวเดียว แล้วส่งครั้งเดียวตั้งแต่ **08:00** เป็นต้นไป (ตั้งค่าได้ที่ `line_digest_hour`) | การ์ดรวม: วันที่แบบไทย + รายการงาน แต่ละบรรทัดมี ชื่องาน · กำหนดกี่โมง · ความสำคัญ · ทำซ้ำ + ปุ่มเปิดแอป                              |

### อะไรทำให้งานกลายเป็น "ความสำคัญสูง"

- ผู้ใช้เลือกเองตอนสร้าง/แก้งาน
- งานที่ระบบสร้างจาก **เอกสารที่อัปโหลด** (เช่น วันหมดอายุกรมธรรม์) ถูกตั้งเป็นสูงอัตโนมัติ

## 2. เรื่องที่ **ไม่** ถูกส่งเข้า LINE (อยู่ในแอปอย่างเดียว)

ทั้งหมดนี้เขียนลงตาราง `app_notifications` ทำให้เกิดจุดแดงบนเมนูและอ่านได้ที่หน้า **การแจ้งเตือน**
แต่ **ไม่ได้เข้าคิวส่ง LINE**

| กลุ่ม              | ชนิด (kind)                                                                                                                  | ใครได้รับ                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **ช่วยฉันที**      | `job_offer` · `job_accepted` · `job_message` · `job_match` · `job_ended` · `job_verified` · `payout`                         | ผู้จ้าง / ผู้ช่วย ตามบทบาทในงานนั้น           |
| **เงินและแพ็กเกจ** | `budget_warning` · `payg_overdue` · `plan_expiring` · `quota` · `billing_result` · `billing_review` · `payment_review`       | เจ้าของบัญชี · `payment_review` ถึง **admin** |
| **แผนงานศพ**       | `funeral_selected` · `funeral_review` · `funeral_evidence` · `funeral_installment` · `funeral_fulfilment` · `funeral_stale`  | เจ้าของแผน · บางชนิดถึง **admin** ที่ต้องตรวจ |
| **ครอบครัว**       | `family_task` · `family_event` · `family_routine` · `family_checkin` · `checkin_missing` · `routine_overdue` · `routine_log` | สมาชิกครอบครัวที่เกี่ยวข้อง                   |
| **เอกสาร**         | `document` · `analyzed` · `attachment` · `insurance` · `bank`                                                                | เจ้าของเอกสาร                                 |
| **อื่น ๆ**         | `provider_contact` · `target` · `test`                                                                                       | ตามเรื่อง                                     |

> ถ้าต้องการให้เรื่องใดในตารางนี้ส่งเข้า LINE ด้วย ต้องเพิ่มการเขียน `notification_log`
> ตอนที่สร้าง `app_notifications` และทำการ์ด Flex ของชนิดนั้น — ตอนนี้ยังไม่มี

## 3. เงื่อนไขที่ทำให้ **ไม่ได้รับ** แม้จะเข้าข่าย

ระบบบันทึกแถวไว้เสมอ (`channel: 'none'`, `status: 'skipped'`) เพื่อให้ตรวจย้อนหลังได้ว่าทำไมเงียบ

| เงื่อนไข                                              | ผล                                                                                             |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| ยังไม่ได้กด **เชื่อมต่อ LINE** ที่หน้าตั้งค่า         | ไม่ส่ง                                                                                         |
| เชื่อมแล้วแต่ **ไม่ได้เป็นเพื่อนกับ OA** หรือบล็อกไว้ | ไม่ส่ง (ตรวจสถานะเพื่อนใหม่ทุก 1 ชั่วโมง)                                                      |
| **โควต้ารายเดือนของ LINE ใกล้หมด**                    | `digest` หยุดก่อนที่ `cap − reserve` (ค่าเริ่มต้น 300 − 50) · `immediate` ส่งต่อได้จนถึง `cap` |
| LINE ตอบ **401/403** (token ผิด)                      | **หยุดส่งทั้งระบบ 6 ชั่วโมง** + เขียน `ai_events` ให้ admin เห็น                               |
| LINE ตอบ **400** (user id ใช้ไม่ได้กับ channel นี้)   | ทำเครื่องหมายว่าลิงก์เสีย ไม่ลองใหม่                                                           |
| LINE ตอบ **429 monthly**                              | โควต้าหมด หยุดรอบนั้น + เขียน `ai_events`                                                      |
| **5xx / timeout / เน็ตล่ม**                           | ลองใหม่รอบถัดไป สูงสุด 3 ครั้ง แล้วถือว่าล้มเหลว                                               |

ค่า `line_monthly_cap`, `line_digest_reserve`, `line_digest_hour` แก้ได้จากฐานข้อมูล
(`notification_settings`) โดยไม่ต้อง deploy

## 4. กันส่งซ้ำ

- งานหนึ่งครั้งที่ถึงกำหนด ถูก **claim** ด้วยการเขียน `notified_at` แบบ atomic — สองรอบที่ชนกันจะมีแค่รอบเดียวที่ได้ไป
- ส่ง LINE พร้อม `X-Line-Retry-Key` ถ้า LINE ตอบ **409** แปลว่ารับไปแล้ว นับเป็นส่งสำเร็จ
- `digest` มีแถวเดียวต่อคนต่อวัน งานที่ถึงกำหนดระหว่างวันจะถูก **ต่อท้าย** แถวเดิม ไม่สร้างใหม่
