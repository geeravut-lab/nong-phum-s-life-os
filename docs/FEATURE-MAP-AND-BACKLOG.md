## เกณฑ์สถานะ (เปลี่ยนแล้ว — อ่านก่อนติ๊ก)

รอบที่แล้วใช้เกณฑ์ว่า "โค้ดมีแล้ว" = ✅ ซึ่งทำให้เอกสารบอกว่าเสร็จทั้งที่ผู้ใช้กดไม่ได้จริง
สาเหตุคือมีการเขียน server function แล้ว import ไว้ แต่ไม่ได้ต่อเข้าปุ่ม — โค้ดคอมไพล์ผ่าน build ผ่าน
แต่ฟีเจอร์ไม่ทำงาน **ห้ามใช้เกณฑ์นั้นอีก**

| สัญลักษณ์ | ความหมาย                                                                  |
| --------- | ------------------------------------------------------------------------- |
| ✅        | **กดใช้งานได้จริงในเบราว์เซอร์แล้ว** (มีคนทดสอบเส้นทางนั้นจริง)           |
| 🧪        | โค้ดครบและ build/typecheck/lint ผ่าน **แต่ยังไม่มีใครทดสอบในเบราว์เซอร์** |
| 🟡        | บางส่วน / MVP / ยังขาดเงื่อนไขภายนอก (เช่น API key)                       |
| ❌        | ยังไม่มี                                                                  |

**กฎ:** ห้ามเปลี่ยน 🧪 → ✅ เพราะอ่านโค้ดแล้วคิดว่าถูก ต้องกดในเบราว์เซอร์จริงก่อน

### ตัวดักไม่ให้เกิดปัญหาเดิม

`eslint.config.js` เปิด `@typescript-eslint/no-unused-vars` เป็น **error** แล้ว (เคยตั้งเป็น `off`)
กฎนี้คือตัวที่จับ "เขียนฟังก์ชันแล้วลืมต่อปุ่ม" — ตอนเปิดกลับมาเจอของตายทันที 10 จุด **ห้ามปิดกฎนี้อีก**
ถ้าต้องมีตัวแปรที่ไม่ได้ใช้จริง ๆ ให้ตั้งชื่อขึ้นต้นด้วย `_`

## Google Places — สิ่งที่ยังต้องยืนยัน

หน้าเว็บมี 3 ข้อผิดพลาดที่ทำให้ "ตั้ง key แล้วแต่ไม่เห็นผล" และแก้แล้วทั้งหมด:

1. `search()` ไม่เคยเรียก Google เลย — เรียกแค่ตัว AI จัดอันดับของในฐานข้อมูล แล้วขึ้นข้อความ "จัดอันดับสถานที่แล้ว"
2. ข้อความ error ถูกซ่อนใน `googlePlaces.length > 0 &&` → แสดงเฉพาะตอน**มี**ผลลัพธ์ ตอนพังจึงไม่เห็นอะไร
3. `catch { /* ignore */ }` กลืน error ทิ้ง

**ยืนยันแล้ว 2026-09-26:** ข้อความที่ขึ้นจริงคือ `Requests from referer <empty> are blocked.`
= **API key ถูกจำกัดด้วย HTTP referrer** แต่ระบบเรียก Places จาก **ฝั่ง server** ซึ่งไม่มี referer ส่งไป
Google จึงบล็อกทุกครั้ง **เป็นปัญหาการตั้งค่า key ที่ Google Cloud ไม่ใช่โค้ด** — ต้องเปลี่ยน key เป็นแบบ
ไม่จำกัด referrer (จำกัดด้วย IP หรือไม่จำกัด แล้วคุมด้วย API restriction: Places API (New) อย่างเดียว)
หรือออก key คนละตัวสำหรับ server

~~**ยังไม่ยืนยัน** ว่า key / Places API (New) / domain restriction ฝั่ง Google ถูกต้อง — ก่อนหน้านี้วินิจฉัยไม่ได้เพราะหน้าเว็บทิ้ง error ทุกตัว
ตอนนี้ถ้ายังมีปัญหา **ข้อความจะขึ้นใต้หัวข้อ "Google Places"**~~ — ซึ่งทำงานตามที่ออกแบบ และเป็นตัวที่ชี้สาเหตุข้างบนให้เจอ

## ช่องกรอกวัน-เวลา — เรื่องที่ยังไม่จบ

`DateTimeInput` / `DateInput` / `TimeInput` ใส่ `lang="en-GB"` เพื่อขอให้เบราว์เซอร์วาดช่องเป็น
วัน-เดือน-ปี แบบ 24 ชั่วโมง **แต่ยืนยันไม่ได้ว่าได้ผลจริง**

ที่เห็นบน production (Chromium ของ Claude): ช่องขึ้นเป็น `mm/dd/yyyy, --:-- --` = เดือนก่อนวัน และ 12 ชั่วโมง
ทดสอบแยกแล้วพบว่า Chromium ตัวนี้วาดเป็น `mm/dd/yyyy` **ทุกกรณี** ไม่ว่าจะตั้ง locale หรือ `--lang` เป็นอะไร
(น่าจะเป็น headless build ที่ไม่มี locale data) จึงใช้เป็นหลักฐานไม่ได้ทั้งสองทาง — พิสูจน์ได้แค่ว่า
`lang` ไม่ช่วยในบิลด์นี้

**สิ่งที่ต้องทำต่อ:** ให้เจ้าของโปรเจกต์เปิดหน้า `/family` หรือ `/agenda` บนเครื่องจริง แล้วดูว่าช่องวัน-เวลา
ขึ้นเป็น `dd/mm/yyyy` + 24 ชม. หรือไม่

- ถ้าถูกแล้ว → ปิดเรื่องนี้ได้
- ถ้ายังเป็น 12 ชม. → ต้องเลิกใช้ช่อง native แล้วทำ control เอง (วัน/เดือน/ปี + เวลา 24 ชม. แยกช่อง)
  เพราะรูปแบบของช่อง native คุมจากหน้าเว็บไม่ได้จริง ๆ

### A. ทำในโค้ดไม่ได้ — ต้องการ credential / บัญชีจากภายนอก

| เรื่อง                                          | ติดที่อะไร                                                                                                                                                                          |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Google Places ใช้งานจริง**                    | key ถูกจำกัดด้วย HTTP referrer แต่เราเรียกจากฝั่ง server ที่ไม่มี referer → ต้องออก key คนละตัวสำหรับ server (จำกัดด้วย IP + Places API (New) อย่างเดียว)                           |
| **LINE OA แจ้งเตือน**                           | env ครบแล้ว ปุ่มสร้าง authorize URL ได้จริง · เหลือ (1) ตรวจ Callback URL ที่ LINE Console (2) กดเชื่อมหนึ่งครั้งด้วยบัญชี LINE จริง — Claude ทำแทนไม่ได้ ดูหัวข้อ "LINE OA" ด้านบน |
| **Email / Calendar / Cloud storage แบบ native** | ต้องจด OAuth app ที่ Google/Microsoft (consent screen, scope, redirect URI) + ใส่ client id/secret เป็น env · ระหว่างนี้ต่อผ่าน **webhook ขาออก** เข้า Make/n8n/Zapier ได้แล้ว      |
| **ระบบรับเงินจริง**                             | PromptPay + สลิปเป็นการยืนยันด้วยคน ยังไม่มี payment gateway ที่ตัดเงินอัตโนมัติ/ออกใบเสร็จภาษี                                                                                     |

### B. ทำได้แต่ยังไม่ได้ทำ (backlog จริง)

| เรื่อง                                   | ทำไมถึงยังไม่ทำ                                                                                             |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **Match score เต็มสเปก**                 | สูตรตรงสเปกแล้ว (35/20/15/10/10/10) แต่ "เวลาว่าง" ยังใช้ข้อมูลหยาบ ๆ ไม่ได้ดูปฏิทินจริง                    |
| **Rules engine: action นอกจากแจ้งเตือน** | ตอนนี้ทุกกฎจบที่ "สร้าง notification" ยังยิง webhook หรือสร้างงานอัตโนมัติจากกฎไม่ได้                       |
| **ค้นหาเนื้อเอกสารภาษาไทย**              | ใช้ trigram (`pg_trgm`) เพราะ Postgres ไม่มี parser ภาษาไทย — ค้นได้แต่จัดอันดับความตรงสู้ full-text ไม่ได้ |
| **Bundle ขนาด**                          | แยก vendor แล้ว (546 → 383 kB) ที่เหลือต้องตัด dependency ออกจริง ๆ                                         |
| **ทดสอบอัตโนมัติ (e2e)**                 | ตอนนี้ทดสอบด้วยการกดจริงเป็นรอบ ๆ ยังไม่มีชุดทดสอบที่รันเองทุก PR                                           |
| **Scenario Analysis เชื่อมข้อมูลจริง**   | ถาม "ถ้า X เปลี่ยน" ได้แล้ว แต่ยังไม่ดึงตัวเลขจริงจาก `/money` มาเป็นฐาน                                    |

### C. โค้ดครบแล้ว แต่ยังไม่มีใครกดทดสอบในเบราว์เซอร์ (🧪)

สถานะ 🧪 ทั้งหมดในตารางข้างบนอยู่ในกองนี้ กองใหญ่ที่สุดคือของรอบที่ 3-4 ซึ่งเขียนไว้ก่อนที่จะมี
ทางให้ Claude ล็อกอินบน production ได้ **ตอนนี้ทดสอบได้แล้ว** จึงเป็นงานที่เดินเก็บได้เรื่อย ๆ
โดยไม่ต้องรออะไรจากใคร — ไล่กดแล้วเปลี่ยน 🧪 → ✅ พร้อมหลักฐาน

ที่ควรไล่ก่อนเพราะเป็นเส้นทางเงินหรือความเป็นส่วนตัว:

1. AI Funeral Planner ครบวงจร (เลือกแพ็ก → admin ยืนยัน → ผ่อน → หลักฐานประกัน)
2. ~~ร้าน/อีเวนต์/โปรโมชันที่ไม่แชร์~~ — **ปิดแล้วรอบที่ 9** ยืนยันด้วย qa2 (เจ้าของ) + qa (admin)
3. ~~คนที่ถูกมอบหมายงานยังเห็นงานเมื่อปิดแชร์~~ — **ปิดแล้วรอบที่ 9**
4. ทดลองใช้ฟรีได้ครั้งเดียวต่อบัญชี
5. ~~Data Export (PDPA)~~ — **ปิดแล้วรอบที่ 9** · ลบบัญชี ยังไม่กด เพราะย้อนกลับไม่ได้
6. สมาชิกครอบครัว **คนที่สาม** ต้องไม่เห็นงานที่ปิดแชร์ — ต้องมีบัญชีทดสอบอีก 1 ใบ

### สิ่งที่ปิดไปแล้วและไม่ต้องตามต่อ

- **ราคา/ต้นทุน AI** — บันทึก token จริงทุกครั้ง + หน้า `/admin/usage` · ย้าย `reasoning` ไป Sonnet 5 (฿1.32 → ฿0.53/ครั้ง) · นับการใช้งานของคนจ่ายเงินแล้ว · Family ให้สิทธิ์ทั้งครอบครัวแล้ว — ดู `docs/PRICING-REVIEW.md`
- **Notification templates** — เก็บ `params` แล้วแปลตอนแสดง + หน้า `/inbox`
- **Integration ขั้นต้น** — webhook ขาออก
- **Rules engine** — 23 กฎที่ admin เปิด/ปิดและตั้งค่าได้
- **ทางให้ Claude ทดสอบบน production** — บัญชีทดสอบ + `*.supabase.co` ใน Network access
- **SMS** — ยกเลิกทั้งระบบโดยเจ้าของโปรเจกต์ (ตรวจแล้วไม่มีโค้ด SMS เหลืออยู่)
- **คู่มือผู้ใช้** — `docs/Life-OS-User-Manual-TH.pdf` 33 หน้า ครบทุกเมนูผู้ใช้ พร้อมแผนผังความเชื่อมโยงระหว่างเมนู · ฉบับปรับปรุงครั้งที่ 2 ตามงานรอบที่ 10-14
