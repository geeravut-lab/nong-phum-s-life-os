## เกณฑ์สถานะ (เปลี่ยนแล้ว — อ่านก่อนติ๊ก)

รอบที่แล้วใช้เกณฑ์ว่า "โค้ดมีแล้ว" = ✅ ซึ่งทำให้เอกสารบอกว่าเสร็จทั้งที่ผู้ใช้กดไม่ได้จริง
สาเหตุคือมีการเขียน server function แล้ว import ไว้ แต่ไม่ได้ต่อเข้าปุ่ม — โค้ดคอมไพล์ผ่าน build ผ่าน
แต่ฟีเจอร์ไม่ทำงาน **ห้ามใช้เกณฑ์นั้นอีก**

| สัญลักษณ์ | ความหมาย                                                                  |
| --------- | ------------------------------------------------------------------------- |
| ✅        | **กดใช้งานได้จริงในเบราว์เซอร์แล้ว** (มีคนทดสอบเส้นทางนั้นจริง)           |
| 🧪        | โค้ดครบและ build/typecheck/lint ผ่าน **แต่ยังไม่มีใครทดสอบในเบราว์เซอร์** |
| 🟡        | บางส่วน / MVP / ยังขาดเงื่อนไขภายนอก (เช่น API key)                       |
| ❌        | ยังไม่มี                                                                  |

**กฎ:** ห้ามเปลี่ยน 🧪 → ✅ เพราะอ่านโค้ดแล้วคิดว่าถูก ต้องกดในเบราว์เซอร์จริงก่อน

### ตัวดักไม่ให้เกิดปัญหาเดิม

`eslint.config.js` เปิด `@typescript-eslint/no-unused-vars` เป็น **error** แล้ว (เคยตั้งเป็น `off`)
กฎนี้คือตัวที่จับ "เขียนฟังก์ชันแล้วลืมต่อปุ่ม" — ตอนเปิดกลับมาเจอของตายทันที 10 จุด **ห้ามปิดกฎนี้อีก**
ถ้าต้องมีตัวแปรที่ไม่ได้ใช้จริง ๆ ให้ตั้งชื่อขึ้นต้นด้วย `_`

## Google Places — สิ่งที่ยังต้องยืนยัน

หน้าเว็บมี 3 ข้อผิดพลาดที่ทำให้ "ตั้ง key แล้วแต่ไม่เห็นผล" และแก้แล้วทั้งหมด:

1. `search()` ไม่เคยเรียก Google เลย — เรียกแค่ตัว AI จัดอันดับของในฐานข้อมูล แล้วขึ้นข้อความ "จัดอันดับสถานที่แล้ว"
2. ข้อความ error ถูกซ่อนใน `googlePlaces.length > 0 &&` → แสดงเฉพาะตอน**มี**ผลลัพธ์ ตอนพังจึงไม่เห็นอะไร
3. `catch { /* ignore */ }` กลืน error ทิ้ง

**ยืนยันแล้ว 2026-09-26:** ข้อความที่ขึ้นจริงคือ `Requests from referer <empty> are blocked.`
= **API key ถูกจำกัดด้วย HTTP referrer** แต่ระบบเรียก Places จาก **ฝั่ง server** ซึ่งไม่มี referer ส่งไป
Google จึงบล็อกทุกครั้ง **เป็นปัญหาการตั้งค่า key ที่ Google Cloud ไม่ใช่โค้ด** — ต้องเปลี่ยน key เป็นแบบ
ไม่จำกัด referrer (จำกัดด้วย IP หรือไม่จำกัด แล้วคุมด้วย API restriction: Places API (New) อย่างเดียว)
หรือออก key คนละตัวสำหรับ server

~~**ยังไม่ยืนยัน** ว่า key / Places API (New) / domain restriction ฝั่ง Google ถูกต้อง — ก่อนหน้านี้วินิจฉัยไม่ได้เพราะหน้าเว็บทิ้ง error ทุกตัว
ตอนนี้ถ้ายังมีปัญหา **ข้อความจะขึ้นใต้หัวข้อ "Google Places"**~~ — ซึ่งทำงานตามที่ออกแบบ และเป็นตัวที่ชี้สาเหตุข้างบนให้เจอ
